Energy-backed neutral settlement layer
PoW with stable memory. Private. Fair.

There are roughly four ways to store and move value today. Fiat is expensive and slow to transact while supply expands silently devaluing principal. Gold has perceived real value but is slow and expensive to transact. Bitcoin is portable but deflationary and transactions are public.

eWatts bridges concepts from all three without replacing any. Supply expands at energy cost, like gold. It is divisible and decentralized, like Bitcoin. But mining uses DRAM, a technology that has been physically flat for 20 years (1-2%/year improvement vs 20-30% for ASICs). No ASIC can shortcut it. A computer from five years ago mines at the same efficiency as one built today.

Dual-layer design: mining is slow and DRAM-bound, creating coins at measurable energy cost. Transactions are fast and private (<3ms per signature). Sender, receiver, and amount are hidden by default.

No pre-mine. No token sale. No founder allocation. No company. Mining is the only way to initially acquire coins.

Architecture Overview

A 3-layer system with rigid separation

eWatts is a deterministic monetary state machine (Layer 1), evaluated under physical substrate hypotheses (Layer 2), and stress-tested in adversarial distributed environments (Layer 3).

Layer 1

PROTOCOL CORE

Deterministic state machine. Execution truth. Block validity, emission, consensus.

Can influence protocol: YES

Layer 2

ECONOMIC HYPOTHESIS

Interpretation layer. Memory-bound vs ASIC-bound stability. Falsifiable.

Can influence protocol: NO

Layer 3

ADVERSARIAL CONSENSUS

Robustness engine. Network noise, fork choice, adversarial objectives.

Can influence protocol: NO

The separation is critical: protocol is verifiable, hypothesis is falsifiable, adversarial layer is experimental. No cross-contamination.

Layer 1

Protocol Core — Deterministic State Machine

A single system of deterministic execution that any node can independently verify.

PROTOCOL CORE S_{t+1} = f(S_t, B_t)

The system is a state machine where S_t is global state (UTXO + commitments + metadata), B_t is a valid block, and f is the deterministic transition function.

Block validity rules

A block is valid if:

  • Proof-of-work satisfies difficulty threshold
  • Previous state exists
  • UTXO transition is consistent
  • Commitments are verifiable
  • Emission invariants are not violated

Emission function (u64 deterministic)

Emission is a function of state and block height. No external input, no discretionary adjustment, no governance tinkering. E_t = g(height, state).

Consensus rule

In absence of network noise: the valid chain is the one with greatest accumulated work (or equivalent substrate-weighted metric defined in Layer 2).

Security invariants

  • No double spend
  • No inflation beyond schedule
  • Deterministic replay
  • State convergence under valid propagation

Layer 2

Economic Hypothesis — Interpretation Layer

Defines the economic meaning of the system without interfering with the protocol.

ECONOMIC HYPOTHESIS

Monetary systems anchored in physical computation substrates exhibit different long-term stability properties depending on the improvement rate of their underlying physical constraints.

Substrate classes

Class A — Energy-bound (ASIC-like): cost approximates energy consumption. Fast efficiency improvement. Competitive hardware arms race.

Class B — Memory-bound (DRAM-latency): cost approximates memory access and latency physics. Slower improvement curve (1-2% annual). More stable cost structure.

Improvement rate differential

Define Δ = rate(substrate improvement). ASIC has high Δ; DRAM latency has low Δ.

Hypothesis: lower Δ yields a more stable monetary emission regime.

Falsifiability conditions

The hypothesis is false if:

  • Substrate advantage converges quickly (Δ becomes irrelevant)
  • System becomes economically dominated by secondary abstraction layer
  • Cost of attack decouples from physical constraint

V3 emission formula

E = total_eff x M(S) x C_node / 1e18

Where total_eff is total effective commitment, M(S) is the bootstrap multiplier (exponential decay from 100,000x), and C_node = $0.0020625/block is the cost-per-node anchor.

Cross-layer boundaries

Layer 2NODoes not define consensus rules
Layer 2NODoes not define validation logic
Layer 2NODoes not affect protocol execution
Interpretative framework only. Measurable. Falsifiable.

See Reflexivity and the Oracle Trap for the structural risk analysis of physically-anchored monetary systems.

Layer 3

Adversarial Consensus — Robustness Engine

Models system behavior under strategic, noisy, and adversarial conditions.

ADVERSARIAL CONSENSUS

Unlike Layer 1's assumption of a single canonical chain, here multiple competing valid chains can exist simultaneously. The system's robustness is measured by how it converges under chaos.

Threat model

Nodes may behave as:

  • Honest
  • Delayed or partitioned
  • Selfish or conflicting-state
  • Withholding-capable

Network model

System operates under latency variance, message duplication, reordering, partial partitions, and probabilistic loss. Adversaries control timing and topology but not cryptography.

Fork choice

Each node selects chain C maximizing:

Score(C) = W(C) - C_attack(C)

Where W(C) is accumulated work and C_attack(C) is a cost-adjusted adversarial penalty model.

System invariants

  • Safety: no double spend
  • Bounded divergence: E[ΔS] < ε
  • Convergence under finite delay
  • Work monotonicity
⚠
Phase 1 adversarial test results

Current implementation validates delay stochasticity, message duplication, partial convergence, and state divergence checks (implemented in shuffle.rs). Explicit adversarial scheduler, formal fork-choice scoring functions, and measurable ΔS metrics are in development for Phase 3.

Features

Core design

Mining runs on standard RAM

No ASICs, no GPUs required. Any computer with RAM can mine. A machine from five years ago performs at the same efficiency as one built today. Explore the economic model.

Private by default

Sender, recipient, and amount are hidden. Each transaction uses ring signatures (11 possible keys), one-time stealth addresses (no two payments to the same person can be linked), and Pedersen commitments that hide amounts while keeping total supply auditable.

Money supply follows energy cost

New coins are emitted proportionally to total network bandwidth. More miners means more emission, but each coin costs energy to mine. The v28 emission formula anchors each eWatt to the energy cost of production.

No pre-mine, no token sale

eWatts has no fundraising, no investor allocation, and no entity controlling its treasury. Mining is the only way to acquire coins. Founder outputs are time-locked on-chain (max(50000, block + 40000)).

Get started

Mine in 5 minutes

You need a computer with Rust installed. Minimum 4 GB of free DRAM. No GPU, no ASIC, no token purchase.

Quick install: curl -sSf https://ewatts.org/install.sh | bash

# Install Rust
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Clone
$ git clone https://github.com/4Ewatts/ewatts-protocol.git
$ cd ewatts-protocol
$ cargo build --release

# Initialize state and mine
$ ./target/release/ewatts-protocol init
$ ./target/release/ewatts-protocol mine

# Start dashboard on port 8080
$ ./target/release/ewatts-protocol dash
